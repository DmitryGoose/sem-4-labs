# Лабораторные работы №4-6. Финансовые продукты API. Backend. Node.js & Express

## Цель работы
Изучение серверной разработки на платформе Node.js с использованием фреймворка Express.js, построение полноценного RESTful API на основе многослойной архитектуры (Routes, Controllers, Services, Data), интеграция CORS-политик, промежуточных обработчиков (middleware), логирования запросов, раздачи статических ресурсов для SPA и централизованной обработки ошибок.

## Задание
Разработать серверную часть веб-приложения для управления финансовыми продуктами (акциями).
Необходимо реализовать:
* **Лабораторная работа №4:** Инициализация Express-сервера на порту 3000, подключение CORS-политик и организация раздачи статических файлов клиентского приложения из папки `public`.
* **Лабораторная работа №5:** Проектирование многослойной архитектуры (разделение на роуты, контроллеры, сервисы) и реализация безопасных эндпоинтов для чтения данных (`GET`).
* **Лабораторная работа №6:** Реализация полного цикла CRUD-операций (`POST`, `PATCH`, `DELETE`) с персистентным сохранением данных в JSON-файле, разработка кастомного middleware-логирования и глобального перехватчика исключений (`500 Internal Server Error`).

## Реализованный функционал
* развернуто Express-приложение, прослушивающее порт 3000;
* реализована чистая многослойная архитектура, изолирующая логику маршрутизации от бизнес-логики и работы с файловой базой данных;
* подключен модуль `cors` для беспрепятственного взаимодействия с фронтенд-сервером сборщика (Webpack Dev Server);
* настроена раздача статического контента (включая HTML-разметку, скомпилированный бандл скриптов `bundle.js` и 3D-модели) из папки `public`;
* реализована корректная работа с клиентским роутингом (клиентский SPA-фолбэк): все GET-запросы, не относящиеся к API, автоматически перенаправляются на `index.html`;
* внедрено кастомное middleware-логирование, выводящее в консоль метод, URL и точное время каждого входящего запроса в формате ISO;
* проектирован и реализован REST API для сущности `/stocks` со следующими эндпоинтами:
  * `GET /stocks` — получение полного списка финансовых продуктов;
  * `GET /stocks/:id` — получение детальной информации о продукте по его ID;
  * `POST /stocks` — создание и добавление нового продукта;
  * `PATCH /stocks/:id` — частичное редактирование параметров существующего продукта;
  * `DELETE /stocks/:id` — удаление продукта из системы;
* интегрирована инициализация и работа с файловой базой данных (`src/data/stocks.json`) через слой сервисов;
* добавлены промежуточные обработчики для обработки несуществующих роутов (бэкенд-маршруты `404 Not Found`) и глобальный обработчик непредвиденных ошибок сервера (`500`).

## Запуск
Порядок запуска:
1. Открыть папку `Lab4_Backend/finance-api` в терминале;
2. Выполнить команду `npm install` для установки всех зависимостей;
3. Запустить сервер в режиме разработки (с поддержкой hot-reload через nodemon) командой: `npm run dev` (или в обычном режиме через `npm run start`).

## Структура проекта
* `public/` — директория статических файлов фронтенда, доступных клиенту напрямую:
  * `index.html` — корневой файл интерфейса;
  * `bundle.js` — скомпилированный фронтенд-скрипт;
  * `money.glb` — 3D-модель для интерфейса;
* `src/index.js` — точка входа, конфигурация промежуточных обработчиков (middleware), статики и запуск сервера;
* `src/routes/stocks.js` — декларация REST-маршрутов для сущности акций и привязка к ним методов контроллера;
* `src/controllers/` — слой извлечения параметров запроса (`req.body`, `req.params`) и формирования JSON-ответов со статус-кодами;
* `src/services/` — слой чистой бизнес-логики и непосредственного взаимодействия с файловой системой;
* `src/data/stocks.json` — файл-хранилище данных, эмулирующий базу данных приложения;
* `package.json` — манифест проекта, содержащий зависимости и скрипты автоматизации запуска (`start`, `dev`).
